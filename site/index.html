Built to work
together.

Give each part of the work the right model, shared knowledge, and a way to pass its results on.

Local and frontier models

Reserve your most capable models for demanding work. Assign local and cloud models to different steps, then change a model without rebuilding the task.

Shared long-term memory

Keep useful knowledge across tasks and models. Enable project memory and learning to store lessons from earlier runs and recall what is relevant to the next task.

Task handoffs and notes

Let related tasks build on each other's work. A task can leave a note for another task's next run, or use its result to trigger a follow-up you have configured.

Models and code, together

Spend model calls on judgment. Run scripts and commands for calculations, transformations and checks, then feed their output into the next model step.

Bring your coding agents

Assign work to Claude Code or Codex, with poieo supplying the schedule and run records. Support for project memory, tools and isolation varies by agent.

You choose the model for each step and how the work flows. Savings and accuracy depend on your models, tasks, and checks.

Install and try the example

The scripted model demonstrates the loop. It does not repair your project or call a real model.

Install and create a project

git clone https://github.com/luceinaltis/poieo
cd poieo
pip install .

mkdir my-board
cd my-board
poieo init --mock

Save a task in tasks/keep-green.yaml

name: keep the tests green
folder: /path/to/your/git-project
prompt: |
  Run the tests. Find and fix a failing test.
  Run them again to check the change.

Choose an existing folder. The mock exercises the loop without calling a real model.

Keep it running

poieo daemon

Open the board at http://127.0.0.1:8484. Then choose the models for your real work.
